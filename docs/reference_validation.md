# Reference-cell validation

The public runner was checked against representative cells generated by the frozen reference environment.
This is a numerical regression check, not a claim of bitwise reproducibility across PyTorch, CUDA, GPU, and
auto_LiRPA versions.

## Shared-start selection

Candidate-pool selection recovered the expected shared starts:

| Protocol | Candidate range | Automatically selected seeds |
|---|---:|---|
| P1 | `[0,25)` | `0,1,4,5,6,7,9,10,11,12` |
| P2 / P6 L=1 | `[0,15)` | `0,1,3,4,5,6,8,9,10,12` |
| P6 L=2 | `[0,25)` | `0,4,5,7,8,10,13,14,18,19` |
| P6 L=3 | `[0,25)` | `1,2,5,8,10,11,12,13,18,21` |

Selection uses SGD for TwoMoons and Adam for MNIST, as encoded in the public YAML files. It runs before
any certified method and does not use certified accuracy to select a seed.

The deeper P1 binary cell is numerically sensitive: in one cross-environment check its fixed-IBP peak was
47.4 rather than 51.5, fixed-IC was 66.2 rather than 66.5, and IC+IWAU was 66.6/66.2 rather than 66.5/66.0
(peak/cert@T). The component ordering and mechanism-level conclusion were unchanged. Exact aggregate tables
should therefore be regenerated in the pinned reference environment, with the dependency and hardware
metadata retained alongside each run.
